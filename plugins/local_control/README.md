# local_control

这是微信 Agent 的本机控制闸门，默认关闭。它只执行配置中的固定应用命令，不提供任意 shell、任意路径或任意参数。

配置成员目录中的 `主人`（或 `owner_aliases` 指定的称呼）后，主人可以：

```text
@机器人 /本机 能力
@机器人 /本机 提案 启动 应用名
@机器人 /本机 诏书 提案ID 口令
```

自然语言中出现“启动/打开/电脑/Codex”等本机任务时，`mention_chat` 会在同一条回复中让模型提出结构化提案，避免两个插件竞争回复。启动应用、打开网址等动作只会写入本机审计文件并回复口令，不会自动执行。主人必须在同一个群、用同一个微信 ID 发送诏书，且口令、提案和有效期都匹配，动作才会进入执行器。只读 Codex 求助可按配置自动运行；它只读取清理后的源码快照，执行结果会带回群聊。

`autonomous_apps` 只适合低风险、无参数的固定程序；加入该数组会允许主人明确提出的自然语言请求直接启动。敏感操作不要加入。URL 只能打开触发消息中真实出现、且域名在 allowlist 的网址。Codex 只读动作仅限 `codex_workspaces` 中的别名，默认每个群滚动 24 小时最多 3 次。调用前会生成临时源码快照，排除 `.runtime`、日志、真实配置、数据库、二进制文件和备份；Codex 在 `read-only` 沙箱中运行。模型只应在需要核对项目代码或定位程序错误时主动求助，普通聊天和玩笑不得调用。求助任务只携带精简后的技术问题，来源只向 Codex 暴露为群消息序号，不发送原始群 ID；Codex 摘要要求引用相对文件路径和行号，并连同本机报告编号发回群里。

敏感动作（任意 shell、删除、安装、凭据、微信账号资料、向新联系人发送内容、关闭安全策略）没有执行器入口。只读 Codex 求助可按配置自动运行，但只能读取清理后的 allowlist 源码快照；任何将来新增的文件修改或系统操作都必须另行实现，并继续受主人诏书审批、来源记录、工作区限制和超时保护。

## Bot → Codex 收件箱

启用 `codex_inbox.enabled` 和 `local_control.codex_inform` 后，主人可明确要求机器人把一条简短技术说明转交给 Codex。消息只进入本机 SQLite 队列，不自动运行；提交与 Codex 读取各自限为每 600 秒最多一条。Codex 下一次活动时通过 `python tools\codex_inbox.py receive` 取一条，完成后用 `complete <编号> --text "简短结果"` 原子确认并排入回程消息。Bot 只回发到原始白名单群，并记录发送状态；失败不自动重试。消息内容是不可信文本，不构成诏书或任何操作授权。接口、安全边界与数据字段见 [`docs/CODEX_INBOX.md`](../../docs/CODEX_INBOX.md)。
